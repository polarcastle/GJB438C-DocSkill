# 句式与表达规范（[25] SPS 适用）

> 生成 `content` 时必须遵守以下规则；写完后逐条自查。

## 1. 陈述句式（强制）

- 规定与要求用"**应**"表述，描述事实用陈述句，不用"必须""要""应该"混用，更不得用"希望""尽量""可能""可以考虑"。
- 每句主语明确（"本CSCI""软件实体""光盘标签"等），一句只表达一个事项。
- 列举交付物采用"文件名＋半角括号类别说明"结构，例如："xtdr.exe（任务调度主程序）、build.bat（环境检查与启动脚本）"。
- 规程类内容按步骤顺序写："先……，再……，若……则……"；异常路径必须写明。

## 2. 量化要求（强制）

- 资源使用数据必须给数值＋单位：处理器占用率（%）、内存容量（MB）、辅存容量（MB）、传输速率（KB/s）。
- 资源使用数据必须注明测量条件（"典型用法：调度1000个任务""最坏情况用法：……"）和测量级别（软件单元级/CSCI级/可执行程序级）。
- 版本号逐项注明（编译程序、操作系统、构建工具），不得只写"最新版本"。
- 数值范围写"0～99"式闭区间并注明单位；百分比写"不超过 30%"。

## 3. 如实陈述原则（强制）

- 某条确实无内容时，写"本CSCI不使用数据库，无数据库设计说明（DBDD）等价文档"或"本条不涉及"，**禁止编造**内容凑数，也禁止留空。
- 包装需求、修改规程等"（若有）"条目：确实没有时如实陈述，不得人为编造。
- 交付物清单（3.1、3.2 条）只列实际存在的文件，禁止列入代码仓库中不存在的文件名；量化指标无依据时标注"待与用户确认"，禁止编造数值。

## 4. 编号与列举格式

- 条内列举用 a）b）c）分级编号，同层编号样式一致（模板原文用 a) 半角括号，替换后的正文统一用 a）全角括号）。
- 交叉引用写"见 3.1条""见5.4条""见6.c）"，章节号与 JSON 中的 `id` 一致。
- 文档名称用书名号《》，首次出现给出编号和版本。

## 5. 禁用表达

- 口语化："东西""搞""大概""差不多""之类的""等等"。
- 营销化："世界领先""极大地""完美"。
- 模糊限定："一般情况下""尽可能""较快""经验证合格"。若确需描述例外条件，写明条件本身（"在……条件下"）。
- 英文缩写首次出现不解释；正文术语与 `references/terminology.md` 不一致。

## 6. 一致性

- 软件名称、缩写、版本号全文一致，且与 `config.json` 封面信息一致。
- 同一交付物全文同一称呼（如统一叫"可执行程序"，不得与"可执行文件"混用）。
- 3.1、3.2 条列出的文件名必须与 4、5、6 章引用的文件名一致。
- 第 6 章引用的章节号（3.2、5.4、《XT-软件需求规格说明》3.10条等）必须真实存在。
