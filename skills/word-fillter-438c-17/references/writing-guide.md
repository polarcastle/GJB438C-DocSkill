# [17] 软件测试记录章节写作要点

> 本文件依据 `GJB438C全套模版/[17]软件测试记录-438C.doc` 中模板的章节说明文字提炼，逐章给出必写内容、写作深度与常见缺陷。生成任何一章的 `content` 前请先阅读本文件对应小节。

## 文件更改记录表（封面后）

- 填写文档版本更改历史：序号、版本号、页次、标记、处数、更改文件号、更改者、日期。
- 首版文档填一行"新建"类记录（标记、更改文件号无则填"—"）；后续版本按实际更改填写。
- 常见缺陷：更改者与日期空缺；处数与更改文件号不对应。

## 第 1 章 范围

### 1.1 标识
- 必写五要素由引擎按 config.json 精确替换生成：a）文档标识号；b）标题；c）软件名称；d）软件缩写；e）软件版本号。标识号格式示例 `TN/x-DO-DS-V{N.xx}`；版本号须与封面"版次"一致。
- 本条 `content` 写一段总述（系统名称＋软件名称＋缩写＋标识号＋版本号＋发布号），不得与 a）～e）明细行重复罗列。
- 常见缺陷：总述中的标识号与封面、页眉不一致；漏写发布号。

### 1.2 被测软件概述
- **已知限制（模板无锚点）**：模板中本节标题下没有任何指导文字段落，引擎没有可锚定的占位文字，生成文档中本节仅有标题、无正文。如需填写被测软件概述（软件用途、组成、运行环境概要），请在生成后于 Word 中手工补充，或将概述内容并入 1.1 标识条的总述。

## 第 2 章 引用文件

- 用表格列出：序号、名称（含编号）、版本、发布日期、来源（编写单位）。
- 至少引用《GJB 438C-2021 军用软件开发文档通用要求》和《软件需求规格说明》。
- 常见缺陷：引用文件与正文实际引用脱节；标准名称不带编号；来源栏写"网络"等不可核查字样。

## 第 3 章 测评环境说明

### 3.1 软硬件环境
- （1）软件环境表：逐项列出测评所用的操作系统、支撑软件、测试工具/测试桩，含名称、版本号、用途、来源（外购/自研/随设备配套）、密级。
- （2）硬件环境表：逐项列出测评所用的计算机、服务器、工作站、测试设备等，含名称、型号、配置、用途、来源、密级。
- （3）环境差异分析表：对比测试环境与软件实际使用环境，说明差异及其对测试结果的影响；无差异时如实写"配置一致，无差异影响"，不得编造差异。
- 常见缺陷：只写"兼容主流配置"不列具体配置；环境差异分析空缺。

## 第 4 章 测试记录（全文核心）

### 4.1 配置项测试记录
- 4.1.1 文档审查测试记录：标题格式「测试类型/测试用例标识」（如文档齐套审查测试/STR-DR-001）；其下的文档齐套审查软件测试记录表为**合并单元格表格，引擎不支持填充**，保留模板空白网格，由测试执行时手工填写。
- 4.1.2 功能测试记录：标题格式「功能测试/用例标识」；第一张功能测试记录表表题（4.1.2.1）由引擎自动编号为表4-2；记录表同为空白网格，手工填写。
- **机制约束（排序）**：project.json 第 4 章 placeholders 数组中，4.1.3（4.1.X 重复原型行）必须排在 4.1.2.1（第一张功能测试记录表表题）**之前**。原因：4.1.2.1 的锚点"表4-X XXX功能测试记录"是 4.1.3 锚点"4.1.X表4-X XXX功能测试记录"的子串，只有先替换原型行，后者才能唯一命中。调整 placeholders 顺序时不得破坏该次序。
- 4.1.3（4.1.X 原型行）：每增加一轮功能测试，复制一轮"表题＋记录表"；content 写「表4-X 软件简称功能测试记录」，"表4-X"原样保留由引擎编号（表4-3、表4-4……）。
- 性能测试记录：标题"性能测试记录"为模板固定文字不改写；`content` 写量化指标要求（数值＋单位＋条件，引自软件需求规格说明或测试说明，无依据标注待确认），其下性能测试记录表（测试次数/性能测试内容或者条件/测试结果）由引擎填充实测数据，"结论"行保留模板原样。
- 4.1.Y 其它测试记录：无其它单独格式记载的测试时，标题写"其它测试记录"、正文如实写"本软件无其它需要单独格式记载的测试记录。"；有则按测试类型命名并逐条陈述。
- 常见缺陷：用例标识与测试说明不一致；指标无单位；记录表表题与表内内容不对应。

### 4.2 系统测试记录
- **已知限制（相同原型标题）**：模板中 4.2 下有 3 个完全相同的原型标题"XXX测试/XXX标识"（4.2.1～4.2.3）。引擎的替换规则无法对文本完全相同的段落给出不同文字，为避免编造重复标题，3 个原型标题由引擎统一置空（生成文档中保留 4.2.1～4.2.3 的空编号标题）。
- 折中写法：各系统测试项的信息（测试类型＋用例标识清单、记录格式说明）在 4.2 正文 `content` 中汇总陈述；生成后请在 Word 中手工重命名或删除 4.2.1～4.2.3 空标题。
- 常见缺陷：系统测试项与配置项测试项混为一谈；只写"系统测试正常"无测试项清单。

## 素材映射

素材收集阶段形成的「项目画像」（开发语言、模块划分、对外接口/API、依赖关系）与测试文档（测试计划、测试说明）是各章内容的事实来源，按下表提取：

| 本章章节 | 提取的信息 |
|----------|------------|
| 1.1 标识 | 软件名称、缩写、版本、标识号：与项目配置管理记录一致 |
| 2 引用文件 | 测试依据文档清单：测试计划、测试说明、软件需求规格说明及标准 |
| 3 测评环境 | 实际搭建的测试环境：操作系统与支撑软件清单、硬件型号配置、与使用环境的差异 |
| 4.1 配置项测试记录 | 测试说明中的用例标识与名称、测试类型划分；需求规格说明中的量化指标（性能指标出处） |
| 4.2 系统测试记录 | 系统测试计划中的测试项与用例标识 |

提取规则：测试用例标识一律沿用测试说明中的编号；未执行的测试不得写入记录；实测数值必须来自测试执行数据，没有执行数据时标注"待测试执行后填写"，不得凭空给数。
