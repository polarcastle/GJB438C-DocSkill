# 军用软件文档常用术语表（[04] SQAP 适用）

> 术语依据 GJB 438C-2021 及 [04] 模板正文用法整理。全文术语必须与本表保持一致；首次出现时用"中文全称（英文缩写）"格式。

## 配置管理与标识

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 计算机软件配置项 | CSCI（Computer Software Configuration Item） | 软件配置项，本计划中"软件"的默认指向；质量保证活动的基本对象。 |
| 配置项 | CI（Configuration Item） | 配置管理的基本单位，本项目中即被保证软件的交付单元。 |
| 基线 | Baseline | 经正式评审确认的配置项集合，作为后续开发工作的基础；基线变更必须受控。 |
| 配置管理 | CM（Configuration Management） | 标识、控制和记录配置项变更的活动；本计划 5.3 条规定其质量保证监督方式。 |
| 文档标识号 | — | 格式示例 `TN/x-DO-DS-V{N.xx}`，见 1.1 节。 |
| 项目唯一的标识符 | — | 文档、评审、问题报告等的唯一编号，用于全项目追踪。 |

## 软件质量保证

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 软件质量保证 | SQA（Software Quality Assurance） | 为了向需方提供软件产品满足质量要求的信任，对软件生存周期内质量活动所实施的统一管理；本文档简称 SQA。 |
| 软件质量保证计划 | SQAP（Software Quality Assurance Plan） | [04] 本文档，规定软件质量保证活动的组织、目标与途径。 |
| 软件质量保证组 | SQAG（Software Quality Assurance Group） | 实施质量保证活动的组织；区分部门级与项目级。 |
| 质量保证报告 | SQAR（Software Quality Assurance Report） | 按本计划编制的过程记录报告，1.3 条述及其依据关系。 |
| 质量审核 | Quality Audit | 对质量活动及其结果进行的系统性独立检查，见第 8 章。 |
| 质量监督 | Quality Surveillance | 对项目开发全过程质量活动的持续监视与督促，见第 8 章。 |
| 代码审查 | Code Review | 对源代码进行系统检查以发现缺陷、统一编码风格的活动，见 4 章质量目标。 |
| 回归测试 | Regression Testing | 问题改正后按规定重新进行的测试，见 5.4.5。 |
| 测试用例通过率 | — | 通过用例数占总用例数之比；质量目标的量化指标（4 章），写法须给出分母定义。 |
| 确认测试 | Qualification Testing | 验证软件满足需求规格说明所规定要求的测试；组织要求见 5.4.1。 |
| 配置项测试 / 系统测试 | — | 软件测试的两个级别，过程管理要求见 5.4；测试人员安排见 5.4.1。 |
| 评审 | Review | 为评价文档或产品质量而组织的正式检查活动，见 5.2；分级：内部评审/正式评审。 |
| 归零 | — | 评审或测试中发现的问题已完成改正并验证关闭。 |

## 文档类型

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 软件开发计划 | SDP（Software Development Plan） | 本计划的关联计划之一（1.4），进度与活动安排的依据。 |
| 软件配置管理计划 | SCMP（Software Configuration Management Plan） | 本计划的关联计划之一（1.4、5.3），配置管理活动的执行文件。 |
| 软件质量保证计划 | SQAP | [04] 本文档。 |
| 软件需求规格说明 | SRS（Software Requirements Specification） | 被保证的技术文档之一，评审与测试的对象。 |
| 软件概要设计说明 | SDD（Software Design Description） | 被保证的技术文档之一，评审与测试的对象。 |
| 软件研制任务书 / 研制总要求 | — | 质量目标（4 章）的来源文件。 |

## 相关方

| 术语 | 含义与使用场景 |
|------|----------------|
| 需方 / 开发方 / 保障机构 | 项目的三类相关方：需求提出方、软件开发方、维护保障组织，1.2 条标识。 |
| 投资方 / 用户 | 项目出资方与软件的实际使用者，1.2 条标识；相关方一律用角色称谓，不得写具体单位名称。 |
| 高层经理 | 质量保证组织中的管理层，负责仲裁与资源保障（3 章）。 |
| 运行现场 | 软件部署使用的地点/环境，区分当前和计划的（1.2 条）。 |

## 通用软件术语（非军用专属，按源码实际出现选用）

> 纯软件、信息化项目正文中高频出现的通用术语。首次出现写"中文全称（英文缩写）"，此后用缩写；源码中未出现的不得收录。

| 术语 | 英文/缩写 | 规范写法与使用场景 |
|------|-----------|----------------|
| 表述性状态转移 | REST（Representational State Transfer） | HTTP 资源接口风格；写接口或测试对象时使用。 |
| JavaScript 对象表示法 | JSON（JavaScript Object Notation） | 数据交换格式；测试数据、记录格式的默认格式。 |
| 超文本传输协议 | HTTP（Hypertext Transfer Protocol） | 接口通信协议；注明方法（GET/POST）、状态码。 |
| 应用程序编程接口 | API（Application Programming Interface） | 对外接口的统称；测试对象描述中使用。 |
| 软件配置管理 | SCM（Software Configuration Management） | 同"配置管理"，正文统一用中文全称。 |

## 术语裁剪指引

- 只收录正文实际出现的术语（与第 9 章 `generation_prompt` 的要求一致）；「通用软件术语」一表按源码实际出现选用，不得为凑数整表照搬。
- 纯软件项目（无硬件配置项）：正文不涉及硬件时，术语表不收 HWCI、物理兼容性等硬件/机电相关术语。
- 本文档为计划类文档：不写"合格性方法"（A-演示/B-测试/C-分析/D-检查/E-特殊方法）与"合格性级别"——那是 [08] 需求类文档的概念；测试要求一律用"测试用例通过率""一次通过率"等量化表述。
- 通用术语与 GJB 术语定义冲突时，以本表 GJB 定义为准，正文避免混用。
