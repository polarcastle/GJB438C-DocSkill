# [25] 软件产品规格说明（SPS）章节写作要点

> 本文件依据 `GJB438C全套模版/[25]软件产品规格说明-438C.doc` 中模板的章节说明文字提炼，逐章给出必写内容、写作深度与常见缺陷。生成任何一章的 `content` 前请先阅读本文件对应小节。

## 第 1 章 范围

### 1.1 标识
- 必写五要素，逐项列出：a）文档标识号；b）标题；c）软件名称；d）软件缩略名；e）版本号（适用时含发布号）。
- 标识号格式示例：`TN/x-DO-DS-V{N.nn}`；版本号须与封面"版次"一致。
- 常见缺陷：漏写软件缩略名或发布号；标识号与文档封面、页眉不一致。

### 1.2 系统概述
- 必写内容：系统与软件的用途；系统与软件的一般特性；开发、运行和维护的历史；需方、用户、开发方和保障机构；当前和计划的运行现场；其他有关文档。
- 写作深度：概述层面，2～3 段，不展开具体文件细节（细节属第 3 章）。
- 常见缺陷：把 3.1/3.2 的文件清单搬进来；缺少相关方和运行现场；不写维护历史。

### 1.3 文档概述
- 必写：本文档的用途和内容概要；使用本文档的保密性要求（如"内部使用，不得外传"）。
- 常见缺陷：只写"本文档描述了……"一句，漏掉保密性要求。

## 第 2 章 引用文档

- 本模板正文**无表格**，引用文档以 a）b）c）分级列举逐条给出。
- 每条必写：编号与名称、编写单位（来源）、版本/修订版、日期，并注明获得途径。
- 须明确陈述：是否存在不能通过正常采购活动得到的文档及其来源。
- 常见缺陷：引用文档与正文实际引用脱节；标准名称不带编号；来源栏写"网络"等不可核查字样。

## 第 3 章 需求（交付物构成）

### 3.1 可执行软件
- 说明电子媒体形式（光盘/U盘/配置库路径等）。
- 用 a）b）c）分级列举安装和运行所需的全部文件：可执行程序、批处理文件、命令文件、配置文件、数据文件等，逐项给出文件名（与交付物实际文件名一致）。
- 结尾必须陈述有效拷贝判据：软件实体须与上述文件精确匹配。
- 常见缺陷：文件名与交付物实际不符；漏掉配置文件或数据文件；没有有效拷贝判据句。

### 3.2 源文件
- 说明电子媒体形式。
- 用 a）b）c）分级列举重新生成可执行软件所需的全部文件：各源代码文件（逐项注明对应软件单元）、构建文件（Makefile/工程文件）、批处理文件、配置文件、数据文件模板。
- 结尾必须陈述有效拷贝判据。
- 常见缺陷：源文件清单与 3.1 的可执行程序对不上（生成关系不清）；漏构建文件，他人无法重新生成。

### 3.3 包装需求
- 交付载体与包装形式；标签应注明的信息项（CSCI名称、标识号、版本号、密级、日期）；储运标志；随盘文件。
- 无包装需求时如实陈述，不得编造。
- 标签信息项必须与封面、1.1 节标识一致。
- 常见缺陷：标签信息缺密级或日期；包装要求与实际交付方式矛盾。

## 第 4 章 合格性规定

- 分别针对**可执行软件**与**源文件**给出证明"有效拷贝"的方法：
  - 可执行软件：对 3.1 条引用的每个文件，检查当前软件中是否存在相同命名的对等实体，通过按位比较或校验和表明相同；
  - 源文件：与 3.2 条引用的文件进行比较（按位比较或校验和）；
  - 有包装需求时补充包装符合性检查。
- 方法必须可操作、可复核，写明比对基准与通过判据；禁止"经验证合格"式空话。
- 常见缺陷：比对基准写错（应是 3.1/3.2 条引用的电子媒体文件）；只写"检查"不写通过判据。

## 第 5 章 软件支持信息

### 5.1 "已建成"软件设计
- 明确设计信息的给出方式：本文档内提供、引用附录，或引用随"已建成"CSCI交付的 SDD/IDD/DBDD 等价文档（引用时给出名称与标识号）。
- 不使用数据库时如实说明无 DBDD 等价文档。
- 源代码清单头文件注释可提供的信息声明不再重复提供。

### 5.2 编译/建立规程
- 用 a）b）c）分级完整覆盖：
  - a）编译程序/汇编程序及版本号；
  - b）其他所需软硬件（含版本号）；
  - c）设置、选项或约定；
  - d）编译/汇编、连接和建立 CSCI 及包含 CSCI 的软件系统的规程，包括对不同现场、配置、版本的变更处理；
  - e）CSCI 级之上建立规程的出处。
- 命令与选项必须与项目实际构建脚本一致，禁止编造不存在的命令。
- 常见缺陷：版本号缺失；不同现场/配置的变更处理不写。

### 5.3 修改规程
- 引言概述修改总体约束（配置管理控制、重新编译建立、回归测试后发布）。
- 模板自带的 a）～e）列举段是必填信息项，逐项改写为实际内容（分别配置在 5.3-a～5.3-e 子条目）：
  - a）保障设施、设备和软件及使用规程；
  - b）数据库/数据文件及使用与修改规程（无数据库时如实陈述）；
  - c）要遵循的设计、编码及其他约定；
  - d）与上述不同的编译/建立规程（无则如实陈述）；
  - e）要遵循的集成和测试规程。
- 常见缺陷：某项无内容时不加说明直接删除；集成测试规程不写回归要求。

### 5.4 计算机硬件资源使用
- 引言说明资源覆盖范围（CSCI 使用需求、系统级资源分配、软件开发计划涉及者）。
- 模板自带的 a）～e）列举段是**每一硬件资源**应说明的五个要素（分别配置在 5.4-a～5.4-e 子条目）：
  - a）得到满足的 CSCI 需求或系统级资源分配（可追踪性见 6.c））；
  - b）使用数据所基于的假设和条件（典型用法、最坏情况用法）；
  - c）影响使用的特殊考虑（虚存、覆盖、多处理器或操作系统开销、库开销）；
  - d）所采用的测度的单位（百分比、每秒周期、字节数、KB/s）；
  - e）已进行的估计或测量的级别（软件单元、CSCI 或可执行程序）。
- 量化数据必须注明测量条件；无实测依据时标注"待与用户确认"，禁止编造。
- 纯软件项目如实说明不涉及专用硬件。

## 第 6 章 需求的可追踪性

- 建立四组双向追踪（分别配置在 6-a～6-d 子条目）：
  - a）每一 CSCI 源文件 → 它实现的软件单元；
  - b）每一软件单元 → 实现它的源文件；
  - c）5.4 条每一资源使用测量 → 它涉及的 CSCI 需求；
  - d）每一资源使用相关的 CSCI 需求 → 5.4 条的使用测量。
- 列举必须完整，源文件与软件单元的对应关系必须与 3.2 条清单和实际代码一致；一对多关系逐条展开。
- 章节号引用必须真实存在。
- 常见缺陷：只写单向；源文件名与 3.2 条不一致。

## 第 7 章 注释

- 有助于理解文档的信息：背景、术语、缩略语、公式。无特殊说明也要给出术语和缩略语表。
- SPS 必备术语：CSCI、有效拷贝、软件单元、校验和、基线；必备缩略语：CSCI、SPS、SDD、IDD、DBDD。

## 从源码到章节的映射

素材收集阶段形成的「项目画像」（开发语言、模块划分、交付物清单、构建配置、依赖关系）是各章内容的事实来源，按下表从用户项目源码与交付物中提取：

| 本章章节 | 从源码/交付物提取的信息 |
|----------|------------------------|
| 1.2 系统概述 | 软件用途与场景：README/项目说明、入口文件职责、交付物构成反映的定位 |
| 3.1 可执行软件 | 发布产物目录（可执行程序、脚本、配置文件、数据文件），逐项取实际文件名 |
| 3.2 源文件 | 源码目录结构（.c/.h/.py 等源文件、Makefile/工程文件），源文件与模块的对应关系 |
| 3.3 包装需求 | 实际交付方式与随交付文档（用户无法确认时提示补充或如实从简） |
| 4 合格性规定 | 比对手段（项目实际使用的校验工具或比对流程） |
| 5.1 已建成软件设计 | 设计文档清单（SDD/IDD 是否随产品交付） |
| 5.2 编译/建立规程 | 构建脚本（Makefile、CI 配置）中的编译器、选项、命令 |
| 5.3 修改规程 | 版本控制与配置管理流程、编码规范文件、测试流程 |
| 5.4 硬件资源使用 | 性能测试记录或运行环境配置；无实测数据时标注"待与用户确认" |
| 6 需求的可追踪性 | 源文件与模块（软件单元）的对应关系、资源需求与测量的对应关系 |

提取规则：模块名、文件名一律沿用代码仓库中的实际命名；代码中不存在的能力、文件、参数不得写入；数值类指标必须有代码、配置或测试记录中的依据，确实没有时标注为待与用户确认，不得凭空给数。
