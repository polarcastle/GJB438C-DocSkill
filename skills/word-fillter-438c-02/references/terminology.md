# 军用软件文档常用术语表（[02] SDP 适用）

> 术语依据 GJB 438C-2021 及 [02] 模板正文用法整理。全文术语必须与本表保持一致；首次出现时用"中文全称（英文缩写）"格式。

## 配置管理与标识

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 计算机软件配置项 | CSCI（Computer Software Configuration Item） | 软件配置项，软件开发、测试和交付的基本对象。SDP 第 5 章各活动围绕 CSCI 展开。 |
| 配置项 | CI（Configuration Item） | 配置管理中受控的基本单位，本项目中即任务调度软件。 |
| 基线 | Baseline | 经正式评审确认的文档/产品版本，后续更改受配置管理控制；风险管理在基线处开展。 |
| 构建版 | Build | 软件开发过程中形成的一个可测试、可评审的软件版本（如初样构建版、正样构建版）。 |
| 项目唯一的标识符 | — | 文档、接口、配置项等的唯一编号，用于全项目追踪。 |
| 文档标识号 | — | 格式示例 `TN/x-DO-DS-V{N.xx}`，见 1.1 节。 |
| 里程碑 | Milestone | 项目进度中标志阶段性成果完成的关键时间点（见第 6 章进度表）。 |

## 文档类型

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 软件开发计划 | SDP（Software Development Plan） | [02] 本文档，软件项目策划的顶层文件。 |
| 软件需求规格说明 | SRS（Software Requirements Specification） | 需求基线文件，第 5 章初样/正样需求分析活动的依据。 |
| 软件概要设计说明 | SDD（Software Design Description） | 概要设计文档，第 5 章设计活动的输出。 |
| 软件配置管理计划 | SCMP（Software Configuration Management Plan） | 配置管理活动的依据，1.4、5.12 引用。 |
| 软件质量保证计划 | SQAP（Software Quality Assurance Plan） | 质量保证活动的依据，1.4、5.14 引用。 |
| 软件研制任务书 | — | 策划约束与合格要求的任务来源文件，第 3、4、5 章多处引用。 |
| 软件版本说明 | SVD（Software Version Description） | 5.9.2、5.10.3 交付文档之一。 |

## 研制阶段与活动

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 生存周期模型 | Software Life Cycle Model | 瀑布、迭代、原型等开发过程模型的统称，4.1 必须明确选定。 |
| 初样 / 正样 | — | 军用软件研制的两个构建版阶段：初样验证需求与设计，正样定型交付。 |
| 单元测试 / 集成测试 | Unit Test / Integration Test | 5.3.6、5.3.7 等规定的测试级别；单元测试白盒、集成测试黑盒。 |
| 配置项测试 | CSCI Test | 对 CSCI 的功能、性能和外部接口测试，独立于开发组实施。 |
| 系统测试 | System Test | 系统级的功能、性能和外部接口测试。 |
| 确认测试 | Validation Test | 出所前确认软件功能和配置是否符合要求（5.4.5）。 |
| 出所检验 | — | 由军代室组织实施的出所前检验（5.6）。 |
| 设计定型 | Design Finalization | 定型测评与设计定型阶段（5.8）。 |
| 回归测试 | Regression Testing | 软件修改后重新测试，验证修改未引入新问题。 |
| 联合技术评审 / 联合管理评审 | Joint Technical/Management Review | 需方与承研方共同参加的两类评审（5.16）。 |
| 非交付软件 | — | 不随合同交付、但保密安全性要求相同的软件（5.2.4）。 |
| 软件开发库 | Software Development Library | 存放开发过程中文档、源代码、数据等的受控库（5.2.2）。 |

## 相关方

| 术语 | 含义与使用场景 |
|------|----------------|
| 需方 / 用户 | 需求提出方与装备使用方；计划中涉及"通知甲方"的表述统一用"需方"。 |
| 开发方 / 承研方 | 承担软件开发任务的单位；全文统一用"承研方"，禁止出现具体单位名称。 |
| 分承制方 | 承担部分研制任务的分承包方（5.17.4）。 |
| 军代室 / 指定评测机构 | 出所检验与定型测评的组织方。 |
| 保障机构 | 软件交付后的维护保障组织。 |

## 通用软件术语（非军用专属，按项目实际出现选用）

> 首次出现写"中文全称（英文缩写）"，此后用缩写；项目中未出现的不得收录。

| 术语 | 英文/缩写 | 规范写法与使用场景 |
|------|-----------|----------------|
| 应用程序编程接口 | API（Application Programming Interface） | 对外接口的统称。 |
| JavaScript 对象表示法 | JSON（JavaScript Object Notation） | 数据交换格式。 |
| 超文本传输协议 | HTTP（Hypertext Transfer Protocol） | 接口通信协议。 |
| 集成开发环境 | IDE（Integrated Development Environment） | 软件工程环境的组成部分（5.2.1）。 |
| 软件配置管理 | SCM（Software Configuration Management） | 基线、变更控制相关活动。 |
| 验证与确认 | V&V（Verification and Validation） | 独立验证和确认机构的相关活动（5.17.5）。 |

## 术语裁剪指引

- 计划类文档不规定具体需求，术语表以研制过程、管理活动、文档类型为主；需求句式专用术语（合格性方法、状态与方式等）不收录。
- 裁剪原则：只收录正文实际出现的术语（与第 8 章 `generation_prompt` 的要求一致）；「通用软件术语」一表按项目实际出现选用，不得为凑数整表照搬。
