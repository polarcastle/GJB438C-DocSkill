# [26] 软件质量保证报告（SQAR）章节写作要点

> 本文件依据 `GJB438C全套模版/[26]软件质量保证报告-438C.doc` 中模板的章节说明文字提炼，逐章给出必写内容、写作深度与常见缺陷。生成任何一章的 `content` 前请先阅读本文件对应小节。

## 模板已知怪癖（填写前必读）

1. **遗留编号标题**：4.5 节的模板原型标题为 "9.5.X 软件XX阶段评审情况"、4.6 节为 "9.6.1/9.6.2 …"，这些编号是从其他文档复制来的遗留物，与本模板实际章节号（4.5/4.6）不一致。project.json 中已用静态规则将它们替换为不带编号的中文标题（"软件正样阶段评审情况"等），由 Word 标题样式自动编号显示为 4.5.1/4.6.1 等。填写时**不要**在 `content` 里手动加这些编号。
2. **4.1.4 的三个四级标题无引导段**："软件需求分析评审""软件设计评审""软件确认测试评审"三个四级标题下没有可替换的引导文字，引擎无法在其下插入正文。写法：把三次评审的完整陈述集中写在 4.1.4 条目中（project.json 已如此配置），三个四级标题保留为结构分节。
3. **4.5.2 与 4.6.2 引导段重复**：模板中这两处的引导文字逐字相同（均为"描述改进落实情况。"），引擎无法用包含锚点区分，采用共用陈述一次性替换两处（`structure.4.duplicate_guidance_shared_content`）。两处显示同一句"评审和第三方测评中提出的建议和意见，项目组均已逐项分析、落实改进并完成验证……"。若需分别描述阶段评审改进与第三方测评改进，请在生成后于 Word 中手动拆分改写。
4. **4.1.5 自带示例内容**：模板该条原文引用了其他课题的《军用中间件课题软件配置管理报告》，已配置为替换目标，填写时会写入本项目的中性表述；不要保留任何"军用中间件"字样。
5. **签署页与更改记录表**：封面后签署页（编制/校对/审核/标审/审定/批准）和"文件更改记录表"不在引擎填写范围，由人工签署，生成后保持原样。

## 第 1 章 范围

### 1.1 标识
- 必写五要素：a）文档标识号；b）标题；c）软件名称；d）软件缩略名；e）软件版本号和发布号。
- 标识号、版本号须与 `config.json` 的 document.id、project.version 逐字一致。
- 常见缺陷：漏写发布号；标识号与 1.1 之外的封面、页眉不一致。

### 1.2 系统概述
- 必写内容：系统和软件的用途；一般特性；开发、运行和维护的历史；需方、用户、开发方和保障机构；当前和计划的运行现场；其他有关文档。
- 写作深度：概述层面，2～3 段；相关方用角色称谓（需方为总体单位、开发方为项目承担单位的软件开发部门等），**禁止编造单位名称**。
- 常见缺陷：把第 3、4 章细节搬进来；相关方只写"有关各方"；运行现场缺失。

### 1.3 文档概述
- 必写：本文档的用途和内容概要；使用本文档的保密性考虑（如"内部使用，不得外传"）。
- 常见缺陷：只写"本文档是质量保证报告"一句，漏掉保密性要求。

## 第 2 章 引用文档

- 用分级编号逐条列出引用文档的编号、标题、修订版（版本）；模板正文无引用表格，以文字列举。
- 应包含：GJB 438C 标准、软件质量保证计划、配置管理计划、软件需求规格说明、软件概要设计说明、软件测试说明；还应标识不能通过正常采购活动得到的文档的来源。
- 常见缺陷：列出正文从未引用的文档；文档编号与 4.3.2 形成的文档不一致。

## 第 3 章 质量目标和要求的完成情况

### 3.1 质量保证组织
- 必写：质量保证工作组的建立情况（组成）；各成员的主要职责（分角色）；各类人员履行质量职责的情况。
- 写作深度：职责到角色级（质量负责人/质量管理员/配置管理员/测试负责人），不出现具体人名。
- 常见缺陷：只写"成立了质保组"无职责分解；职责与 4 章活动脱节。

### 3.2 质量目标完成情况
- 必写：按《软件质量保证计划》建立质量保证体系的情况；质量目标分解；**每条目标给出目标值和达成值**（文档齐套率、评审问题闭环率、测试覆盖率、交付物合格率）。
- 常见缺陷：目标无量化（"质量良好"）；只有目标值没有实测/达成值。

### 3.3 质量要求完成情况
- 必写：软件实现的功能满足使用要求的情况（功能清单与范围一致）；性能实测结果与战术技术指标的对比（实测值＋指标值）；满足总体技术方案要求的情况。
- 量化指标须以测试报告为依据，无依据时标注"待与用户确认"，禁止编造。
- 常见缺陷：只写"满足要求"无数值对比；功能清单与软件实际模块不符。

## 第 4 章 质量管理

### 章引言（structure.4.content）
- 概述执行质量管理体系文件和《软件质量保证计划》的情况；列举对设计质量、测试质量和最终产品质量采取的主要控制措施；一句"实施情况详见本章各条"引出下文。

### 4.1.1 设计和开发策划
- 必写：策划阶段明确的质量保证内容——质量特性及实现措施、文档编制计划、评审计划、测试策划、质量控制点和检查单；策划结果形成的计划文档及评审情况。

### 4.1.2 设计和开发确认
- 必写：确认准则（需求规格说明、研制任务书）；确认方法（确认测试）；确认环境；确认记录。

### 4.1.3 设计和开发验证
- 必写：验证活动安排（分阶段及转入准则）；验证方法（评审、分析、审查、测试）；验证记录；验证结论。

### 4.1.4 设计和开发评审活动
- 必写：与模板预留的三个四级标题对应的三次评审（软件需求分析评审、软件设计评审、软件确认测试评审）各自的审查内容、提出问题数及归零情况、评审结论。
- 机制约束：三个四级标题下无引导段，评审陈述集中写在本条；内容按"1）2）3）"分评审各一行书写。
- 常见缺陷：只写"进行了评审"无问题数和归零情况；编造评审次数。

### 4.1.5 设计和开发变更控制
- 必写：更改纳入配置管理、更改受控流程（申请/评审/批准/实施/回归验证）；引用《软件配置管理报告》。
- 常见缺陷：保留模板自带的其他课题报告名称（"军用中间件课题"必须替换）。

### 4.2 测试过程
- 必写：在质量管理部门及相关人员监督下完成单元测试、集成测试、配置项测试、系统测试和确认测试的情况；质量保证措施——用例评审、记录完整、问题闭环、需求覆盖率实测值、测试报告编制与归档。
- 常见缺陷：测试层级写漏（五个层级缺一不可）；覆盖率无实测值。

### 4.3.1 文档编制要求
- 必写：按生存周期阶段明确文档编制要求；文档格式标准（GJB 438C）；校对、审核、标审环节；齐套情况。

### 4.3.2 形成的文档
- 必写：正样提交时的所有技术文档名称及编号，逐条列出（需求规格说明、概要设计说明、测试说明、测试报告、配置管理报告、质量保证报告等）。
- 常见缺陷：编号与第 2 章引用文档不一致；漏列本报告自身。

### 4.4 软件配置管理过程
- 必写：配置管理总体实施情况；基线管理和受控管理；开发库、受控库和产品库的控制和管理情况。

### 4.5 阶段评审过程（包括内部评审）
- 原型标题已配置替换为"软件正样阶段评审情况"（可按项目实际阶段改名，如"软件初样阶段评审情况"）。
- 4.5.1 评审结论和建议：必写评审组织情况、评审结论（通过/不通过）、逐条评审建议和意见。
- 4.5.2 改进落实情况：引擎以共用陈述一次性填写（见"模板已知怪癖"3），生成后可手动改为本阶段的具体改进项。
- 常见缺陷：结论与建议混在一起；建议无落实闭环。

### 4.6 第三方测评情况
- 4.6.1 测评结果和评价结论及建议：必写委托具备资质的第三方测评机构的情况（不写机构名称，除非用户提供）、测评内容（功能/性能/安全性/代码质量）、测评结论、逐条建议。
- 4.6.2 改进落实情况：同 4.5.2，共用陈述填写，生成后可手动改写。
- 常见缺陷：编造测评机构名称或测评结论；建议与 4.5.1 重复无增量信息。

## 第 5 章 项目风险监控

- 必写：依据《软件质量保证计划》的风险监控机制（识别、分析评估、应对措施、责任人、跟踪）；主要风险及应对情况逐条列出；总体结论（风险受控）。
- 常见缺陷：只写机制无实际风险项；风险项与项目实际无关。

## 第 6 章 记录的管理情况

- 必写：质量保证各项活动信息的记录情况（评审记录、测试记录、审核和监督记录）；记录的标识、归档、保存期限和调阅。
- 常见缺陷：只写"有记录"不列记录类别；保存期限缺失。

## 第 7 章 质量审核和质量监督的落实

- 必写：质量审核（次数、范围、问题整改）；质量监督（对文档、软件测试、方案评审、需求分析评审、设计评审、第三方测试、开发计划执行情况及进度的跟踪监督）；监督记录归档。
- 常见缺陷：审核与监督混淆；只写"进行了监督"无对象清单。

## 第 8 章 注解

- 如实陈述：无补充事项时写"本文档无需要补充的注解事项"；有术语或背景补充时在此给出。

## 素材来源与章节映射

质量保证报告是总结报告，内容以项目质量记录为依据（而非源码），素材收集阶段按以下映射提取：

| 本文档章节 | 素材来源 |
|------------|----------|
| 1.2 系统概述 | 建设方案/README、软件开发计划、需求规格说明 |
| 3.1 质量保证组织 | 软件质量保证计划中的组织与职责章节 |
| 3.2 质量目标完成情况 | 软件质量保证计划中的质量目标、阶段检查记录 |
| 3.3 质量要求完成情况 | 研制任务书/可研报告指标、软件测试报告实测数据 |
| 4.1 各条 | 软件开发计划、评审记录、确认/验证记录 |
| 4.2 测试过程 | 软件测试说明、软件测试报告、问题跟踪单 |
| 4.3.2 形成的文档 | 配置管理计划交付物清单、产品库清单 |
| 4.4 软件配置管理过程 | 软件配置管理报告 |
| 4.5 阶段评审过程 | 阶段评审申请、评审意见、归零证明 |
| 4.6 第三方测评情况 | 第三方测评报告（无则如实说明未开展） |
| 第 5 章 项目风险监控 | 风险管理记录、会议纪要 |
| 第 6/7 章 | 质量记录清单、审核和监督记录 |

提取规则：评审次数、问题数、覆盖率、指标实测值等数值必须来自真实记录，确实没有时标注"待与用户确认"，不得凭空给数；单位名称、机构名称、人名缺失时用角色称谓代替并列入收尾确认清单。
