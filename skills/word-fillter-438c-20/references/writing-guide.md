# [20] 软件用户手册（SUM）章节写作要点

> 本文件依据 `GJB438C全套模版/[20]软件用户手册-438C.doc` 中模板的章节说明文字提炼，逐章给出必写内容、写作深度与常见缺陷。生成任何一章的 `content` 前请先阅读本文件对应小节。

## 第 1 章 范围

### 1.1 标识
- 必写五要素，逐项列出：标识号、名称、缩略名、版本号、发布号（模板 1.1 下的五行标识由引擎按 config.json 精确替换，本段 content 用一段话复述同一信息，两处必须一致）。
- 标识号格式示例：`XT-SUM-V1.0`；版本号须与封面"版次"一致。
- 常见缺陷：content 中的标识与 config.json 不一致；漏写发布号。

### 1.2 系统概述
- 必写内容：系统和软件的用途；一般特性；开发、运行和维护的历史；需方、用户、开发方和保障机构；当前和计划的运行现场；其他有关文档。
- 写作深度：概述层面，2～3 段，不展开操作细节（细节属第 3、5 章）。
- 相关方只写角色定位（"需方为示例系统建设单位"），**不得出现具体单位名称**。
- 常见缺陷：把操作手册内容搬进来与第 5 章重复；缺少运行现场与维护历史。

### 1.3 文档概述
- 必写：本文档的用途和内容概要；使用本文档的保密性要求（如"内部资料，不得对外复制、传播"）。
- 常见缺陷：只写"本文档描述了……"一句，漏掉保密性要求。

## 第 2 章 引用文档

- **本模板的引用文档为正文段落陈述，无表格**。按"编号、标题、编写单位、修订版、日期"逐条列出，用 1）2）3）编号。
- 须标识不能通过正常采购活动得到的文档的来源。
- 常见缺陷：引用文档与正文实际引用脱节；标准名称不带编号；编写单位写成具体单位实名（应写"项目承建单位"等角色）。

## 第 3 章 软件综述

### 3.1 软件应用
- 简要说明软件预期用途；描述对软件使用所期望的能力、运行改进和受益情况（用"可期望获得以下能力提升"引出）。

### 3.2 软件清单
- 标识使软件运行必须安装的所有软件文件（含数据库和数据文件），逐文件列出：文件名、用途、保密性考虑。
- 必写：紧急时刻继续或恢复运行所需软件的标识（主程序＋配置文件＋其备份）。
- 常见缺陷：漏写数据文件；漏写紧急恢复所需软件。

### 3.3 软件环境
- placeholder 级 content 为一句总起；a）～e）子条逐项填写：
  - a）计算机设备：数量、内存数量、辅存数量、外围设备（打印机、输入/输出设备）；
  - b）通信设备；c）其他软件（操作系统、数据库、数据文件、实用程序、支持系统）；
  - d）表格、规程或其他手工操作；e）其他设施、设备或资源。
- 无该项时写"无。……不需要……"并说明理由，**不得编造**。
- 子条 content 必须保留模板原有编号字母（a）b）c）d）e））。

### 3.4 软件组织和操作概述
- placeholder 级 content 为引言段（逻辑部件划分）；a）～d）及 b）下 1）～7）逐项填写：
  - a）各逻辑部件的用途/操作（从用户角度，写操作入口）；
  - b）性能特性，1）～7）逐项：可接受输入的类型/数量/速率；输出类型/数量/准确性/速率；典型响应时间及影响因素；典型处理时间及影响因素；限制（如可追踪事件数目）；预期错误率；预期可靠性（MTBF）。
  - c）软件功能与接口系统、组织或位置的关系；d）管理监控措施（口令、权限、日志）。
- 性能特性**必须量化**；无源码/设计依据的数值标注"待与用户确认"，不得编造。
- 子条 content 必须保留模板原有编号（a）b）c）d）与 1）～7））。

### 3.5 意外事故及运行的备用状态和方式
- 说明紧急时刻以及不同运行状态/方式下用户处理软件的差异；给出进入/退出各状态的用户操作路径。
- 不需要多种状态时如实陈述"除上述状态外，本软件不区分其他运行方式"。

### 3.6 保密性
- 概述与软件相关的保密性考虑；适用时包括对软件或文档非授权复制的警告信息（"警告：……非授权复制均违反保密管理规定"）。

### 3.7 帮助和问题报告
- 标识联系方式、获得帮助的途径（联机帮助/本手册章节）、报告问题的规程（问题报告应含现象、时间、步骤、日志、联系方式）。

## 第 4 章 软件入门

### 4.1 软件的首次用户
- 本条为引导条，模板无指导文字，placeholder 不写 content；其下 4.1.1～4.1.3 三个子条分别填写。

### 4.1.1 熟悉设备
- placeholder 级 content 为一句引导（"需要时，本条应描述的内容如下"）；a）～e）逐项填写：打开与调节电源规程；显示屏幕大小与能力；光标形状/定位/使用；键盘布局与点击设备功能；关闭电源的特殊顺序规程。
- 软件为纯后台服务、无本地界面时，如实说明用户通过远程终端操作，相应条目写实际使用的设备。

### 4.1.2 访问控制
- placeholder 级 content 为一句引导；a）～c）逐项填写：如何获得口令；如何添加/删除/更改口令；输出报告及媒体的存储与加标记保密性考虑。

### 4.1.3 安装和设置
- 描述访问或安装软件、执行安装、配置软件、删除或覆盖以前的文件或数据、输入软件操作参数必须执行的规程。
- 写成可执行的编号步骤；涉及覆盖旧数据时必须提示先完成备份（引用 5.5）。

### 4.2 启动
- 提供开始工作的逐步规程（编号步骤），包括任何可用的选项（如启动参数）。
- 必写：遇到问题时用于问题确定的检查单（分 a）b）c）列出常见故障及检查项）。

### 4.3 停止和挂起
- 描述如何停止或中断软件使用；如何判断是正常结束还是异常停止（给出判别准则，如状态栏显示、任务中断标记）。

## 第 5 章 使用指南

- 本章引言（章节级 content）：说明本章的组织方式与使用对象，提及"警告""注意"标记的约定。

### 5.1 能力
- 简述事务、菜单、功能或其他处理相互之间的关系（数据流/操作流视角），给出主要菜单路径。

### 5.2 约定
- 描述软件使用的约定：显示颜色、警告铃声、缩略语表（指向第 6 章）、命名或编码规则（任务标识格式、日志命名、日期格式）。

### 5.3 处理规程（机制约束，重要）
- 模板中本小节仅含一个 `5.3.X(软件使用方面)` 原型标题及其指导段落。本 skill 的引擎对该原型采用**静态填充**：
  - placeholder 级 `content` 会**整体替换该三级标题的文本**，故 content 必须写成新的标题行，格式为「5.3.1 ＋使用方面名称」（如"5.3.1 任务调度处理"）；
  - 子条 `5.3.1` 的 `content` 为正文，写入该使用方面的完整规程。
- 因模板只有一个 5.3.X 原型，输出文档只生成一个 5.3.1 条目。软件有多个使用方面时，**在 5.3.1 的 content 内以分段或 a）b）c）分别描述**，禁止为凑结构编造软件中不存在的功能；如实际软件确需按多个方面分条成册，按模板说明将使用规程拆到后续章（第 6 章及以后）并在 5.3.1 中引用。
- 规程正文必写要素：功能描述、菜单与数据项、用户输入及约束、输出、诊断或错误消息、报警、帮助工具；描述风格前后一致（对菜单的描述保持一致，对事务描述保持一致）。
- 常见缺陷：placeholder 级 content 写成正文段落而非标题行；规程缺输入约束或错误处理说明。

### 5.4 有关的处理
- 标识并描述未被用户直接调用、且 5.3 未描述的批处理、脱机处理或后台处理；说明支持这种处理的用户责任（如保证设备不关机、检查存储空间）。

### 5.5 数据备份
- 描述创建和保留备份数据的规程：备份对象（配置文件、数据文件）、频率（每日/每周）、保留策略（保留最近 N 周）、介质管理与标记、备份在恢复中的用途（引用 5.6）。

### 5.6 错误、故障和紧急情况下的恢复
- 给出从错误或故障中重启或恢复的详细规程（按场景分步，注明判别条件）；给出紧急事件下确保运行连续性的规程（与 3.5 呼应）。

### 5.7 消息
- 列出完成用户功能时可能发生的所有错误消息、诊断消息；逐条给出：消息编号与名称、含义、出现后要采取的动作。
- 编号规则全文一致（如 E-XXXX 错误、W-XXXX 警告、I-XXXX 提示）；只列软件实际会产生的消息。

### 5.8 快速参考指南
- 提供或引用快速参考卡：常用功能键、控制序列、格式、命令或其他使用方面的速查。

## 第 6 章 注释

- 有助于理解文档的信息：背景、术语、缩略语、公式。无特殊说明也要给出术语和缩略语表，只收录正文实际出现的术语。
- 术语格式：「中文术语（英文全称，缩写）：中文定义」；缩略语格式：「缩写 - 英文全称（中文全称）」。

## 从源码到章节的映射

素材收集阶段形成的「项目画像」（开发语言、模块划分、入口、对外接口/API、关键类与函数、依赖关系）是各章内容的事实来源，按下表从用户项目源码中提取：

| 本章章节 | 从源码提取的信息 |
|----------|------------------|
| 1.2 系统概述 | 软件用途与场景：README/项目说明、入口文件职责、依赖清单反映的定位 |
| 3.1 软件应用 | 软件预期用途与面向用户的改进点 |
| 3.2 软件清单 | 构建/打包产物清单（可执行文件、配置文件、数据文件），部署包内容 |
| 3.3 软件环境 | 部署文档、容器/脚本中的资源设定、依赖清单（package.json、pom.xml 等） |
| 3.4 软件组织和操作概述 | 从用户可见角度划分逻辑部件（前端页面/服务/脚本）；接口与通信方式；配置项中的限制值（队列长度、超时、重试次数）支撑性能特性量化 |
| 4.1.3 / 4.2 安装与启动 | 安装脚本、启动命令、命令行参数定义（argparse/flag 等）、配置文件样例 |
| 5.2 约定 | 界面文案、日志格式、错误码定义、命名规范 |
| 5.3 处理规程 | 界面路由/菜单结构、表单与参数校验逻辑、主要业务流程 |
| 5.4 有关的处理 | 定时任务、cron 表达式、后台线程/守护进程 |
| 5.5 / 5.6 备份与恢复 | 数据文件位置、持久化机制、部署文档中的运维规程 |
| 5.7 消息 | 错误码/消息定义文件、日志中的错误分支、异常处理代码 |

提取规则：模块名、菜单名、参数名、文件名一律沿用代码中的命名；代码中不存在的功能、界面元素、消息不得写入；数值类指标必须有代码或配置中的依据，确实没有时标注为待与用户确认，不得凭空给数。
