# 句式与表达规范（[21] 计算机编程手册适用）

> 生成 `content` 时必须遵守以下规则；写完后逐条自查。

## 1. 陈述句式（强制）

- 一律用陈述句客观描述，主语明确（“目标计算机”“本系统”“处理器”等），一条只说明一项内容。
- 能力与特性用“**应**”“**支持**”“**采用**”表述，不用“必须”“要”“应该”混用，更不得用“希望”“尽量”“可能”“可以考虑”。
- 禁止写成对使用人员的操作指令（如“你可以……”“请注意……”），手册只陈述系统事实。

## 2. 量化要求（强制）

- 技术参数必须给数值＋单位：时钟周期（ns）、主频（MHz）、字长（位）、存储容量（MB）、传输速率（bit/s、Mbit/s）、执行时间（周期数、ms）。
- 资源类参数必须给出测量或适用条件（如“处理 10000 行源代码时”“连续运行 24 h 时”）。
- 数值范围写“0～99”式闭区间并注明单位；百分比写“不超过 80%”，不写“小于 80% 左右”。
- 寄存器、地址、指令助记符的写法与目标机数据手册保持一致（如 `R0～R31`、`0x4000_0000`）。

## 3. 如实陈述原则（强制）

- 某条确实无内容时，写“本系统不涉及……”或“无……”，**禁止编造**技术参数凑数，也禁止留空。
- 无附加编程技术、无专用编程手段等情况，直接如实说明，不得人为区分或虚构。

## 4. 编号与列举格式

- 条内列举用 a）b）c）、1）2）3）分级编号，同层编号样式一致；模板子条固定的字母编号（a～j）逐项保留，内容替换进对应子条。
- 交叉引用写“见 3.2.1”“见 4.3.5”，章节号与 JSON 中的 `id` 一致。
- 文档名称用书名号《》，首次出现给出编号和版本。

## 5. 禁用表达

- 口语化：“东西”“搞”“大概”“差不多”“之类的”“等等”。
- 营销化：“世界领先”“极大地”“完美”。
- 模糊限定：“一般情况下”“尽可能”“较快”。若确需描述例外条件，写明条件本身（“在……条件下”）。
- 英文缩写首次出现不解释；正文术语与 `references/terminology.md` 不一致。

## 6. 一致性

- 系统名称、软件缩写、版本号全文一致，且与 `config.json` 封面信息一致。
- 同一部件全文同一称呼（如统一叫“目标计算机”，不得与“目标机”混用）。
- 第 3 章的操作信息参数（字长、容量、速率）与第 4 章编程特征中的对应描述必须一致。
