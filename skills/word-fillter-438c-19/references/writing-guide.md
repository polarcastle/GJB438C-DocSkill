# [19] 软件测试报告（STR）章节写作要点

> 本文件依据 `GJB438C全套模版/[19]软件测试报告-438C.doc` 中模板的章节说明文字提炼。生成任何一章的 `content` 前请先阅读本文件对应小节。

## 第 1 章 范围

### 1.1 标识
- 描述**系统和软件**的完整标识（模板原文为"系统加软件"）：标识号、名称、缩略名、版本号和发布号；与封面 config.json 完全一致。

### 1.2 系统概述
- 概述**系统和软件**的用途与一般特性；开发、运行和维护的历史（阶段与时间点，如实陈述）；需方、用户、开发方和保障机构的标识（无明确信息时如实写"按项目合同执行，本文档不列出具体名称"，**禁止编造单位名**）；当前和计划的运行现场；其他有关文档（列名称与编号）。
- 常见缺陷：漏写"系统"层面直接写软件；历史写成计划；运行现场笼统写"实验室"。

### 1.3 文档概述
- 本文档的用途（记录测试环境、过程与结果，作为验收依据）和内容；保密性要求（密级与传播限制，与封面密级一致）。

## 第 2 章 引用文档

- 列出编号、标题、编写单位、修订版及日期；标识不能通过正常采购活动得到的文档的来源。
- 通常须引用：GJB 438C 标准本身、对应 SRS、软件测试计划（STP）、软件测试规程（STD）。
- 常见缺陷：只列标准不列项目文档；版本日期与封面时间线矛盾。

## 第 3 章 测试结果概述

### 3.1 对被测试软件的总体评估（本章灵魂）
- a) 总体评估：实测数据（用例数、通过数、通过率、覆盖测试项）＋对照 SRS 的满足性结论＋明确"通过/不通过"判断。**数字必须与两张统计表和第 4 章一致**。
- b) 所有遗留的缺陷、限制或约束：逐项给出问题/更改报告编号；没有遗留时如实写"无"。
- c) 每个遗留缺陷三要素：①对软件和系统性能的影响（标识未满足的需求及 SRS 章节号）；②纠正时对软件和系统设计的影响（影响范围限定到模块/配置项级别）；③推荐的纠正方案/方法（含回归范围与计划版本）。
- ｄ) 各轮次按问题类型、问题等级的数据统计表（表3-1、表3-2）：合计行＝全部轮次累计发现的问题数；回归轮次的"已纠正/新引入/未纠正"行为当轮处置情况。
- 常见缺陷：评估无数、用例数与统计表矛盾、遗留缺陷无报告编号、纠正方案无回归安排。

### 3.2 测试环境的影响
- 逐项对比测试环境与操作环境的差异（硬件、软件版本、数据、人员、网络），每项给出对测试结果影响的评估；最后给综合评估结论。
- 常见缺陷：只列差异不评影响；"无差异"时不逐项确认就下结论。

### 3.3 改进建议
- 针对被测软件的设计、操作或测试提出建议，每条＝建议内容＋对软件的影响；建议应来自测试实际发现，与第 4 章问题/偏差呼应。
- 无建议时如实陈述，不得凑数。

## 第 4 章 详细测试结果

> 模板说明："测试"一词指一组相关测试用例的集合。本章按测试项组织。

### 4.X（测试的项目唯一的标识符）
- 每个测试项一节（如"功能测试"）。**机制说明**：本模板标题为 Word 自动多级编号，`4.X`/`4.X.2.Y` 等是原型标题中的字面 instructional 文字；填写时用实际名称整段替换标题文本（如"功能测试""测试用例TC-FUN-003"），条号由自动编号生成（4.1、4.1.2.1 等）。**有多个测试项时，在 Word 中对已填好的 4.1 节整块复制并改标题与内容**；本 skill 的 JSON 填写覆盖一个完整测试项原型。

### 4.X.1 测试结果总结
- 测试项标识＋用例总量＋按完成状态分组（如预期/遇到问题/与要求有偏差），列出用例标识范围；非"所预期的"必须引用 4.X.2/4.X.3 子条（写自动编号后的真实条号，如 4.1.2.1）。
- 常见缺陷：只写"全部通过"不列用例范围；引用的子条号与实际编号不符。

### 4.X.2.Y（遇到问题的测试用例）
- 每个遇到问题的用例一小节，五要素齐全：a) 问题简述（含问题类型与等级）；b) 出问题的测试规程步骤（规程标识＋步骤号）；c) 问题/更改报告与数据引用（无则写"不适用"）；d) 改正重复的规程/步骤次数及每次结果；e) 再测试的回退点/恢复步骤。

### 4.X.3.Y（与测试用例/规程不一致的用例）
- 每个偏差用例一小节，三要素齐全：a) 偏差说明（运行情况＋偏差性质归类，如替换设备、未遵循步骤）；b) 偏差理由（客观原因与等效性论证）；c) 对测试用例有效性影响的评估（明确"有效/无效"结论及依据）。

## 第 5 章 注释

- 背景、术语、缩略语、公式等有助于理解文档的信息；只收录正文实际出现的术语与缩略语，格式见 `terminology.md`。

## 从素材到章节的映射

素材收集阶段形成的事实来源（测试管理系统导出、测试记录、问题单、被测软件源码）按下表提取：

| 本章章节 | 提取的信息 |
|----------|------------|
| 1.2 系统概述 | 项目文档中的开发历史、运行现场；被测软件源码的模块划分佐证软件特性描述 |
| 第 2 章 引用文档 | 测试依据文档清单（SRS/STP/STD 编号与版本），与配置管理系统记录一致 |
| 3.1 总体评估与统计表 | 测试执行记录（用例数、通过数）、问题单台账（类型、等级、轮次、处置状态）；**数字必须三方一致（记录/台账/报告）** |
| 3.2 测试环境影响 | 测试环境清单与操作环境基线的逐项对比记录 |
| 3.3 改进建议 | 测试过程评审记录、缺陷根因分析结论 |
| 4.X.1 测试结果总结 | 测试用例执行清单及完成状态标注 |
| 4.X.2.Y 遇到的问题 | 问题用例的执行日志、规程步骤号、问题/更改报告编号、重复执行记录 |
| 4.X.3.Y 不一致 | 偏差审批记录、替代设备论证材料 |

提取规则：测试用例、问题报告编号沿用测试管理台账中的原标识，保持全文一致；台账中不存在的用例、问题、偏差不得写入；数字无法核实时为"待与用户确认"项，按 SKILL.md 收尾汇总流程处理。
