# [24] 软件版本说明（SVD）章节写作要点

> 本文件依据 `GJB438C全套模版/[24]软件版本说明-438C.doc` 中模板的章节说明文字提炼，逐章给出必写内容、写作深度与常见缺陷。生成任何一章的 `content` 前请先阅读本文件对应小节。

## 第 1 章 范围

### 1.1 标识
- 必写要素，逐项列出：文档标识号、标题、软件名称、软件缩写、软件版本号，适用时加发布号。
- 标识号格式示例：`TN/x-DO-DS-V{N.xx}`；版本号须与封面"版次"一致，发布号格式全文统一（如 Release 1）。
- 常见缺陷：漏写软件缩写或发布号；标识号与文档封面、页眉不一致。

### 1.2 系统概述
- 必写内容：系统与软件的用途；一般特性；开发、运行和维护的历史；需方、用户、开发方和保障机构；当前和计划的运行现场；其他有关文档。
- 写作深度：概述层面，2～3 段，不展开发布细节（细节属第 3 章）。
- 常见缺陷：把材料清单搬进来与 3.1 重复；缺少相关方和运行现场；不写维护历史。

### 1.3 文档概述
- 必写：本文档的用途和内容概要；使用本文档的保密性要求（如"内部使用，不得外传"）。
- 常见缺陷：只写"本文档描述了……"一句，漏掉保密性要求。

## 第 2 章 引用文档

- 列出引用文档的编号、标题、编写单位、修订版及日期；须标识不能通过正常采购活动得到的文档的来源。
- 常见缺陷：引用文档与正文实际引用脱节；标准名称不带编号；来源栏写"网络"等不可核查字样。

## 第 3 章 版本说明（全文核心）

### 3.1 发布的材料清单
- 按标识号、标题、缩略名、日期、版本号和发布号，列出构成所发布软件的所有物理媒体（如列表、磁带、磁盘、光盘）和有关的文档，逐项写全六要素。
- 必写：适用这些项的保密性考虑；处理它们的安全措施（如对静电和磁场的关注）；关于复制与许可证条款的说明及约束。
- 常见缺陷：只列介质不写文档；缺保密性考虑和复制许可说明；六要素不全。

### 3.2 软件内容清单
- 按标识号、标题、缩略词语、日期、版本号和发布号列出构成所发布软件版本的所有计算机文件（可执行程序、配置文件、数据文件）。
- 必写：适用的保密性考虑。
- 常见缺陷：文件名与交付介质实际文件不一致；只列可执行程序漏掉配置和数据文件。

### 3.3 更改说明
- 列出自上一个版本后引入当前版本的所有更改；使用更改类别时按类别划分。
- 每条更改标识相关的问题报告、更改建议和更改通告，以及对系统运行和其他软硬件接口的影响。
- **如实陈述原则**：本条不适用于初始软件版本——首版发布时直接写"本版本为初始发布版本，无上一个版本可比较，本条不适用"，**禁止编造**更改记录。

### 3.4 适应性数据
- 标识或引用包含在软件版本中的所有现场专用数据；第一版之后的版本描述对适应性数据做的更改。
- 无现场专用数据时如实陈述，并说明运行参数的管理方式。

### 3.5 有关的文档
- 按标识号、标题、缩略名、日期、版本号和发布号列出与所发布软件有关但未包含在其中的所有文档（如 SRS、SDD、测试报告、验收文档）。
- 常见缺陷：与 3.1 随介质交付的文档混淆（这里是"未包含在其中"的文档）。

### 3.6 安装说明
- 覆盖五项信息：a）安装软件版本的说明；b）为使该版本可用而应安装的其他更改的标识（含场地唯一的适应性数据）；c）与安装有关的保密性和提示；d）判定版本是否正确安装的规程；e）安装中遇到问题后的求助联系地点。
- **机制说明（重要）**：模板把指导文字分散在 5 个段落中——引言句+a）项在本条 `content` 书写；b）c）d）e）四项分别由 `3.6.1`～`3.6.4` placeholder 承接（模板的 a）b）两项在同一段落，`3.6.1` 的锚点覆盖该段，content 只写 b）项）。填写时不要把五项全部堆进 3.6 的 `content`。
- d）项写成可执行的检查命令或步骤（如运行"scheduler.exe -v"核对版本号）；e）项写具体联系渠道，无具体联系方式时写"通过配置管理渠道提交问题报告"。

### 3.7 可能的问题和已知的错误
- 描述发布时可能发生的问题和已知的错误、解决步骤、识别/避免/纠正的说明（直接或通过引用）或其他处理措施。
- 给出的信息应适合预期接受者：用户机构需要避免错误的建议；保障机构需要改正错误的建议。
- 常见缺陷：只列现象不给规避/纠正措施；经测试无已知错误时不写"未发现"而留空。

## 第 4 章 注释

- 有助于了解文档的信息：背景、术语、缩略语、公式。无特殊说明也要给出术语和缩略语表。
- 只收录正文实际出现的术语与缩略语；术语每条一行"中文术语（英文缩写）：定义"，缩略语每条一行"缩写 - 英文全称（中文全称）"。

## 从源码到章节的映射

素材收集阶段形成的「项目画像」（开发语言、模块划分、入口、构建产物、依赖关系）是各章内容的事实来源，按下表从用户项目源码中提取：

| 本章章节 | 从源码提取的信息 |
|----------|------------------|
| 1.2 系统概述 | 软件用途与场景：README/项目说明、入口文件职责、依赖清单反映的定位 |
| 3.1 发布的材料清单 | 交付物清单（构建产物、安装包、文档），发布介质形式由用户提供 |
| 3.2 软件内容清单 | 构建输出的实际文件名：可执行程序、配置文件、数据文件（取自构建脚本/打包脚本） |
| 3.3 更改说明 | 版本控制历史（自上一基线后的提交）、变更记录、问题跟踪单 |
| 3.4 适应性数据 | 配置文件、环境变量、启动参数中随现场变化的项 |
| 3.5 有关的文档 | 配置库中文档清单（需求、设计、测试、验收文档） |
| 3.6 安装说明 | 部署脚本、安装程序行为、版本自检命令 |
| 3.7 可能的问题和已知的错误 | 测试遗留问题清单、缺陷跟踪系统中遗留的已知缺陷 |

提取规则：文件名、模块名、命令名一律沿用代码与构建产物中的实际命名；代码/配置库中不存在的文件、更改、问题不得写入；发布介质形式、联系地点等源码无法支撑的信息，提示用户补充或如实从简。
