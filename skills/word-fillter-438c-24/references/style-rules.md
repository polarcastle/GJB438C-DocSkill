# 句式与表达规范（[24] SVD 适用）

> 生成 `content` 时必须遵守以下规则；写完后逐条自查。

## 1. 陈述句式（强制）

- SVD 是描述性文档，正文用客观陈述句（"本版本包含……""本条给出……"），不用"应""必须"等需求句式（那是 SRS 的写法）。
- 每条信息是完整陈述句，主语明确（"本软件""本版本""本次发布"等），一条只陈述一个事实。
- 列举清单项用 a）b）c）、1）2）3）分级编号，同层编号样式一致；清单项内容写全要素，不以"等"字收尾。

## 2. 要素完整要求（强制）

- 材料清单（3.1）和内容清单（3.2、3.5）中的每一项必须写全六要素：标识号、标题、缩略名、日期、版本号、发布号；缺项时如实说明缺项原因。
- 量化描述必须给数值＋单位：数量（张、个）、容量（MB、GB）、时间（天、h）；不得只写"若干""适量"。
- 安装检查规程（3.6 d）写成可执行的步骤或命令，不得只写"按规程检查"。

## 3. 如实陈述原则（强制）

- 某条确实无内容时，写"本条不适用""无……"并说明原因（如"本版本为初始发布版本，无上一个版本可比较"），**禁止编造**材料、文件、更改记录或已知错误凑数，也禁止留空。
- 无现场专用适应性数据、无其他必装更改等情况，直接如实说明，不得人为编造。

## 4. 编号与列举格式

- 条内列举用 a）b）c）、1）2）3）编号，同层编号样式一致。
- 交叉引用写"见 3.1""见《任务调度软件用户手册》"，文档名称用书名号《》，首次出现给出编号和版本。
- 引用 GJB 438C 标准时写明标准号和年份（如《GJB 438C-2021》）。

## 5. 禁用表达

- 口语化："东西""搞""大概""差不多""之类的""等等"。
- 营销化："世界领先""极大地""完美"。
- 模糊限定："一般情况下""尽可能""较快"。若确需描述例外条件，写明条件本身（"在……条件下"）。
- 英文缩写首次出现不解释；正文术语与 `references/terminology.md` 不一致。

## 6. 一致性

- 软件名称、缩写、版本号、发布号全文一致，且与 `config.json` 封面信息一致。
- 第 3 章各条引用的文档标识号、文件名必须与交付介质中的实际名称一致；同一文档全文同一称呼。
- 3.3 更改说明、3.7 已知错误中引用的版本号必须与 1.1 标识中的版本号对应关系正确。
