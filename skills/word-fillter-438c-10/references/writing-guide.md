# [10] 软件概要设计说明（SDD）章节写作要点

> 本文件依据 `GJB438C全套模版/[10]软件概要设计说明-438C.doc` 中模板的章节说明文字提炼。生成任何一章的 `content` 前请先阅读本文件对应小节。

## 第 1 章 范围

### 1.1 标识
- 描述**系统和软件**的完整标识（比 SRS 多"系统"）：a）文档标识号；b）标题；c）软件名称；d）软件缩写；e）软件版本号。

### 1.2 系统概述
- 概述**系统和软件**的用途；系统与软件的一般特性；开发、运行和维护的历史；需方、用户、开发方和保障机构；当前和计划的运行现场；其他有关文档。

### 1.3 文档概述
- 本文档的用途和内容；使用本文档的保密性要求。

## 第 2 章 引用文档

- 表格列出编号、标题、编写单位、修订版及日期；标识非正常采购来源。通常须引用 GJB 438C 本身和对应 SRS。

## 第 3 章 系统设计决策（本章灵魂）

- 给出两类决策：①**系统行为设计决策**——忽略内部实现、从用户角度描述系统如何运转以满足需求；②**影响软件部件选择与设计的其他决策**。
- 叙述规则：
  - 需求中已明确或要推迟到部件设计时确定的决策，**如实陈述**，不得编造；
  - 针对关键性需求（安全性、保密性关键）的决策在专门章条叙述；
  - 决策依赖系统状态或方式的，指明该依赖性；
  - 给出或引用理解这些决策所需的设计约定（命名、分层、接口风格等）。
- 决策内容范围（模板示例 a～e）：
  - a）系统接收的输入和产生的输出的设计决策，包括与其他系统、HWCI、CSCI 和用户的接口（已写入 IDD 的可直接引用）；
  - b）响应每个输入或条件的系统行为：执行动作、响应时间等性能特性、物理系统模型化说明、选定的方程式/算法/规则、对不允许的输入或条件的处理；
  - c）数据库/数据文件如何呈现给用户（已写入 DBDD 的可直接引用）；
  - d）为满足安全性和保密性需求所选的方法；
  - e）为满足灵活性、可用性、可维护性所选的方法。
- 常见缺陷：写成需求复述而不是"决定怎么做"；决策无理由；出现"见详细设计"式空话。

## 第 4 章 系统体系结构设计

### 4.X CSCI（每个 CSCI 一节）
- CSCI 划分要对应系统结构，每个 CSCI 给出 4 个子条；设计信息多处出现时只写一次、其余引用；依赖系统状态/方式的须指明。

### 4.X.1 CSCI 概述
- 本 CSCI 的职责定位、在系统中的角色、与其他 CSCI 的协作关系。

### 4.X.2 CSCI 部件设计
- a）列出构成该 CSCI 的**所有软件部件**，每个部件赋予**项目唯一的标识符**。部件是设计元素（类、对象、模块、函数、例程、数据库），可分层、可嵌套；一个数据库可作为一个 CSCI 也可作为一个部件；
- b）部件间的**静态关系**（组成/调用/继承等，与所选设计方法学一致：面向对象给出类与对象结构及模块过程结构）；
- c）每个部件的**用途**，并指明分配给它的 CSCI 需求和 CSCI 级/系统级设计决策；
- d）每个部件的**开发状态/类型**：新开发、按原样重用、再工程、为重用而开发等；重用的须给标识信息（名字、版本、文档引用、库）；
- e）计划使用的**计算机硬件资源**，逐项覆盖 5 要素：①得到满足的需求或系统级资源分配；②使用数据基于的假设和条件（典型/最坏情况）；③特殊考虑（虚存、覆盖、多处理器、OS 与库开销）；④测度单位（处理器能力百分比、周期/秒、内存字节数、千字节/秒）；⑤测量级别（部件/CSCI/可执行程序）；
- f）每个部件的软件放置的**程序库**。

### 4.X.3 执行方案
- 描述部件间的**动态关系**（运行期间相互作用），图表＋文字：执行控制流程、数据流、动态控制序列、状态转换图、时序图、部件间优先关系、中断处理、时序/排序关系、例外处理、并发执行、动态分配与去分配、对象/进程/任务的动态创建与删除。
- 常见缺陷：只写"模块 A 调用模块 B"，无动态行为（异常、并发、时序）。

### 4.X.4 接口设计
- 4.X.4.1 接口标识和接口图：每个接口给项目唯一标识符；用名称、编号、版本及文档引用标识接口实体（软件部件、系统、配置项、用户）；说明固定特性实体与在开发实体；用接口图描述。
- 4.X.4.1.X 每个接口按需覆盖（与 SRS 3.3.X 同构）：a）优先级；b）接口类型；c）数据元素特征（9 项：标识/类型/大小格式/单位/范围枚举/准确性精度/约束/保密性/来源接收者）；d）数据组合体特征（8 项）；e）通信方法特征；f）协议特征；g）物理兼容性等其他特征。
- 未涵盖在本 SDD 内的实体（如外部系统）的接口特性作为假设陈述，或用"当[未涵盖的实体]这样做时，[所指定的实体]将……"句式。
- 可引用数据字典、协议标准、用户接口标准代替详述。

## 第 5 章 需求可追踪性

- 必须包含**双向**：
  - a）从本 SDD 标识的每个软件单元，到分配给它的 CSCI 需求（正向：需求→单元）；
  - b）从每个 CSCI 需求，到被分配这些需求的软件单元（逆向）。
- 追踪对象是对应 SRS 的章节，章节号必须真实对应；一对多逐条展开。

## 第 6 章 注释

- 背景、术语、缩略语、公式等有助于理解文档的信息。

## 从源码到章节的映射

素材收集阶段形成的「项目画像」（开发语言、模块划分、入口、对外接口/API、关键类与函数、依赖关系）是各章内容的事实来源，按下表从用户项目源码中提取：

| 本章章节 | 从源码提取的信息 |
|----------|------------------|
| 第 3 章 系统设计决策 | 架构模式与框架选型（目录结构、核心类、配置归纳）；关键机制如缓存、队列、并发模型的选择及其理由 |
| 4.X.1 CSCI 概述 | CSCI 划分对应代码的顶层模块/服务边界，职责取自各模块入口与 README |
| 4.X.2 部件设计 | 类/包结构 → 软件部件及项目唯一标识；继承、组合、调用关系 → 静态关系；类与函数的注释/职责 → 部件用途；第三方库与复用代码 → 开发状态/类型（重用项注明名称版本） |
| 4.X.2 e）硬件资源 | 部署配置、容器/脚本中的 CPU、内存、存储设定及代码中的池化/缓存规模 |
| 4.X.3 执行方案 | 调用链、事件/消息流、线程与并发模型、异常处理与重试路径（从流程编排代码、异步机制、catch/finally 结构归纳） |
| 4.X.4 接口设计 | 对外 API、函数签名、请求/响应消息格式、协议与通信方式 |
| 第 5 章 需求可追踪性 | 软件单元名称/标识回指第 4 章 cscis 定义，需求章节号回指对应 SRS，均需与源码模块对应 |

提取规则：软件部件、CSCI、接口的命名沿用代码中的模块/类/接口名，保持全文一致；代码中不存在的部件、接口、决策不得写入；动态行为（时序、并发、异常路径）必须有代码机制支撑，确实无法从源码判断时提示用户补充或如实从简。
