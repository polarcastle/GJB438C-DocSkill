# [09] 接口需求规格说明（IRS）章节写作要点

> 本文件依据 `GJB438C全套模版/[09]接口需求规格说明-438C.doc` 中模板的章节说明文字提炼，逐章给出必写内容、写作深度与常见缺陷。生成任何一章的 `content` 前请先阅读本文件对应小节。

## 第 1 章 范围

### 1.1 标识
- 五要素标识行（文档标识号、标题、软件名称、软件缩写、软件版本号）由 `config.json` 的 exact 规则自动填写，本条 `content` 用一段话概述系统与软件的完整标识（标识号、名称、缩略名、版本号、发布号），与五要素行保持一致。
- 常见缺陷：content 中的版本号、标识号与 config.json 封面信息不一致；漏写发布号。

### 1.2 系统概述
- 必写内容：系统与软件的用途；系统与软件的一般性质；开发、运行和维护的历史；投资方、需方、用户、开发方和保障机构；当前和计划的运行现场；其它有关文档。
- 写作深度：概述层面，2～3 段，不展开接口细节（细节属第 3 章）。
- 常见缺陷：把第 3 章接口清单搬进来重复；缺少相关方和运行现场；不写维护历史。

### 1.3 文档概述
- 必写：本文档的用途和内容概要；与使用有关的保密性或私密性考虑（如"内部使用，不得外传"）。
- 常见缺陷：只写"本文档描述了……"一句，漏掉保密性要求。

## 第 2 章 引用文档
- 用表格列出：序号、名称（含编号）、版本、发布日期、来源；须标识不能通过正常采购活动得到的文档的来源。
- 常见缺陷：引用文档与正文实际引用脱节（第 3 章引用的数据字典、接口说明必须能在本章找到）；标准名称不带编号；来源栏写"网络"等不可核查字样。

## 第 3 章 需求（全文核心）

### 3.1 接口标识和接口图（动态章节）
- placeholder 级 `content` 是本节引言，必写：本文档标识的接口总数、每个接口的项目唯一标识符、各接口的接口实体（系统、配置项、用户等）、哪些实体具有固定的接口特性（要给出这些实体的接口需求）、哪些实体正在开发或修改；（若适用）说明接口图。
- **机制约束**：引擎将本节视为动态章节，`subsections` 中每个子条生成一个二级标题（3.2、3.3……）和正文，**`subsections` 不允许为空**（空则报错）。当实际只有一个接口时，**禁止编造多个接口凑数**——只建一个子条，首句如实标识该接口及其项目唯一标识符。
- 子条 `name` 会作为章节标题（引擎生成"3.2任务数据接口"式标题，编号与名称之间无空格），**必须以中文开头**；子条中的 `replacement_pattern` 字段在动态模式下被引擎静默忽略，无需填写。
- **编号联动（重要）**：子条数量决定后续章节编号。示例配置 2 个接口（3.2、3.3），因此"需求的优先顺序和关键性"标题占位符（id `3.4`）写为"3.4 需求的优先顺序和关键性"。**增删接口子条时，必须同步改写 id `3.4` 占位符 content 中的章节号**（N 个接口时为 3.{N+2}）。

### 3.2～3.{N+1} 接口子条（每个接口一个）
- 首句：一句话简要标识接口实体、项目唯一标识符。
- 之后按 a.～g. 分行组织（与模板原型条目一致），无内容的项如实写"无"或"不适用"：
  - a. 接口优先级：相对优先关系，以及与软件内部其它处理的优先关系；
  - b. 接口类型：实时数据传送、数据的储存和检索等；
  - c. 数据元素特性：名称/标识（项目唯一标识符、非技术名称、技术名称、缩略名）、数据类型、大小和格式、计量单位、取值范围或枚举、准确性和精度、优先级别/时序/频率/容量/序列等约束、保密性约束、来源和接收者；
  - d. 数据元素包特性：名称/标识、包内数据元素及其结构、介质及结构、视听特性、包间关系、约束、保密性约束、来源和接收者；
  - e. 通信方法特性：链接/带宽/频率/介质、消息格式、流控制、传送速率与间隔、路由寻址命名、传输服务、安全性/保密性考虑；
  - f. 协议特性：项目唯一标识符、优先级别/层次、打包、合法性检查/错误控制/恢复、同步、状态标识与报告；
  - g. 其它特性：物理兼容性（尺寸、公差、负载、接插件）、电压等。
- **关键句式**：未涵盖实体的特性作为假定陈述，用"当[未涵盖的实体]这么做时，本软件应……"表述，不得对外部实体提需求。
- 可引用其它文档（数据字典、通信协议标准、用户接口标准、IDD）代替详述。
- 常见缺陷：接口无项目唯一标识符；数据元素缺单位、取值范围；把对外部系统的要求写进本文档。

### 3.{N+2} 需求的优先顺序和关键性
- 必写：各需求的优先顺序、重要程度或权值；标识对安全性、保密或私密性起关键作用的需求以特殊处理；全部同等重要时如实描述。
- 常见缺陷：优先级与前述接口子条的优先级项矛盾；忘记同步标题编号（见 3.1 编号联动）。

## 第 4 章 合格性规定
- 必写：定义一组合格性方法，并为第 3 章每个需求指定确保其满足所使用的方法（可在第 3 章需求条目中注明，也可用表格表述——本模板未设表格，正文表述即可）。
- 五类方法（模板 a.～e. 各占一个占位符 4.1～4.5，逐条改写为项目实际用法）：演示（直接运行接口实体）、测试（仪器/专用测试设备采集数据）、分析（处理积累数据）、审查（目视检查）、特殊的合格性方法（专用工具/技术/规程/设施/验收限制）。
- 常见缺陷：只抄方法定义不落到本项目（应写明每类方法验证第 3 章哪些接口需求）；方法与需求明显不匹配（如数据格式需求选"演示"）。

## 第 5 章 需求可追踪性
- 系统级接口实体：本章不适用，如实说明即可；子系统级或更低级接口实体：必写 a.（正向）与 b.（逆向）两条。
- 正向（占位符 5.1）：本文档中实体的每个需求 → 所涉及的系统（或子系统）需求；也可通过对第 3 章每个需求注释提供追踪。
- 逆向（占位符 5.2）：分配给本接口实体的、影响某个接口的每个系统（或子系统）需求 → 本文档中涉及它的接口需求。
- 模板中"注：每个层次的系统细化都可能导致不能直接追踪到较高层次需求的需求……"一段为模板固有注释，引擎不改动，保留在文档中，属正常现象。
- 常见缺陷：声称可追踪却给不出对应章节号；来源文档（如 SRS）未列入第 2 章引用文档。

## 第 6 章 注解
- 有助于理解文档的一般信息：背景、词汇表、原理；按字母顺序列出所有字头词、缩略语及本文档中的含义，以及理解本文档所需的术语和定义。
- 只收录正文实际出现的术语与缩略语（与第 6 章 `generation_prompt` 一致），术语与 `references/terminology.md` 保持一致。

## 从源码到章节的映射

素材收集阶段形成的「项目画像」（开发语言、模块划分、入口、对外接口/API、关键类与函数、依赖关系）是各章内容的事实来源，按下表从用户项目源码中提取：

| 本章章节 | 从源码提取的信息 |
|----------|------------------|
| 1.2 系统概述 | 软件用途与场景：README/项目说明、入口文件职责、依赖清单反映的定位 |
| 3.1 接口标识和接口图 | 对外 API 路由/函数签名、协议/端口/队列等连接配置，确定接口清单与项目唯一标识符 |
| 3.2～ 接口子条 | 请求与响应的数据结构（字段名→数据元素名）、通信协议与数据格式、超时/重试/缓冲等参数、错误处理与校验逻辑 |
| 3.y 优先顺序 | 代码中的调度优先级、超时处置、降级策略所反映的重要程度 |
| 第 4 章合格性规定 | 不直接取自源码：按各接口需求的验证可行性选取方法，引用第 3 章实际接口编号 |
| 第 5 章可追踪性 | 不直接取自源码：追踪到 SRS/系统需求的条目需用户确认，引用第 3 章实际编号 |

提取规则：接口名、数据元素名、函数名一律沿用代码中的命名；代码中不存在的接口、数据元素、参数不得写入；数值类指标必须有代码或配置中的依据，确实没有时标注为待与用户确认，不得凭空给数。
