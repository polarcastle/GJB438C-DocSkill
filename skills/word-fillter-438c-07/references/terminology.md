# 军用软件文档常用术语表（[07] 安全性大纲适用）

> 术语依据 GJB 438C-2021 及 [07] 模板正文用法整理。全文术语必须与本表保持一致；首次出现时用"中文全称（英文缩写）"格式。只收录正文实际出现的术语，不得照搬通用词表凑数。

## 配置管理与标识

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 计算机软件配置项 | CSCI（Computer Software Configuration Item） | 软件配置项，文档编制与配置管理的基本对象；本文档以整个软件为对象开展安全性工作。 |
| 项目唯一的标识符 | — | 文档、需求、数据记录等的唯一编号，用于全项目追踪；1.1 节文档标识号格式示例 `TN/x-DO-DS-V{N.xx}`。 |
| 基线 | Baseline | 经正式评审确认的文档/产品版本，后续更改受配置管理控制；本大纲的制定和修改按配置管理程序评审和审批。 |
| 文档标识号 | — | 1.1 节标识项 a），见封面与页眉标识。 |
| 软件配置管理 | SCM（Software Configuration Management） | 4.2.9 安全保障要求中"安全配置管理"活动的上位概念。 |

## 文档类型

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 软件安全性大纲 | SSP（Software Safety Program） | [07] 本文档，规定软件生存周期各阶段的安全性要求与安全性活动安排。 |
| 软件开发计划 | SDP（Software Development Plan） | 本大纲应纳入的顶层计划文件，培训计划、安全任务日程表与其协调一致。 |
| 软件研制任务书 | — | 合同/任务来源文件；4.2.1 可行性论证对其中安全性要求进行评审和论证。 |
| 软件需求规格说明 | SRS（Software Requirements Specification） | 需求分析阶段安全需求细化的来源文档，可列为引用文档。 |
| 软件概要设计说明 / 软件详细设计说明 | SDD / — | 概要设计、详细设计阶段安全性设计的载体文档；评审活动的对象。 |

## 安全性工作术语（本文档核心）

| 术语 | 英文/缩写 | 含义与使用场景 |
|------|-----------|----------------|
| 软件安全性 | Software Safety | 软件在规定的条件下不造成人员、财产和物理环境意外危险的特性；全文核心对象。 |
| 安全性大纲 | Safety Program | 规定软件生存周期各阶段安全性工作项目、责任与进度的顶层文件，即本文档。 |
| 安全性目标 | Safety Objective | 各阶段要达成的安全性水平，须定量、定性结合给出（4.2.2 b）。 |
| 安全性目标分配 | Safety Objective Allocation | 将系统/软件安全性目标分解到各软件部件的设计活动（3.1 概要设计阶段、4.2.5 a）。 |
| 安全关键功能 | Safety-Critical Function | 失效可能导致危险后果的功能，须重点分析并单独标识（4.2.5 c）。 |
| 故障模式、影响及危害度分析 | FMECA（Failure Mode, Effects and Criticality Analysis） | 4.2.5 b 所列安全性分析项目，识别故障模式及其影响与危害度。 |
| 软件安全性分析 | Software Safety Analysis | 4.2.5 规定的九类分析活动总称：目标分配、FMECA、安全关键功能、接口、数据、保密性、冗余、余量、抗攻击分析。 |
| 安全性事件 | Safety Event | 4.2.7 要求记录与监视的关键安全事件，如任务失控、超时、资源耗尽。 |
| 安全性度量 | Safety Measurement | 3.2 规定的定性估计/定量预测与测量活动，用于各阶段关键安全性问题的及时发现。 |
| 安全性验证和确认 | Safety V&V | 4.2.6.4 评审对象：验证软件安全性是否达到预定目标的方法与活动。 |
| 余量分析 / 冗余分析 | Margin Analysis / Redundancy Analysis | 4.2.5 g）、h）所列分析项：资源余量与容错冗余设计分析。 |
| 危险 | Hazard | 可能导致伤害或损失的潜在状态；可行性论证阶段进行危险识别与风险估计。 |
| 生存周期阶段 | Life Cycle Phase | 3.1 所列八个阶段：可行性研究与计划、需求分析、概要设计、详细设计、实现、组装测试、确认测试、使用和维护。 |

## 通用软件术语（按源码实际出现选用）

> 纯软件、信息化项目正文中高频出现的通用术语。首次出现写"中文全称（英文缩写）"，此后用缩写；源码中未出现的不得收录。

| 术语 | 英文/缩写 | 规范写法与使用场景 |
|------|-----------|----------------|
| 表述性状态转移 | REST（Representational State Transfer） | HTTP 资源接口风格；写接口运行环境时使用。 |
| JavaScript 对象表示法 | JSON（JavaScript Object Notation） | 数据交换格式；数据记录文件、日志格式的默认格式。 |
| 超文本传输协议 | HTTP（Hypertext Transfer Protocol） | 接口通信协议；注明方法与状态码。 |
| 应用程序编程接口 | API（Application Programming Interface） | 对外接口的统称。 |
| 审计日志 | Audit Log | 安全关键操作留痕的记录，4.2.7 数据记录要求的载体。 |

## 术语裁剪指引

- 只收录正文实际出现的术语；「通用软件术语」一表按源码实际出现选用，不得整表照搬。
- 本文档为计划/大纲类文档，不写合格性方法、需求追踪等验证类术语；正文如引用验证活动，用"安全性验证和确认"即可。
- 通用术语与 GJB 术语定义冲突时，以本表 GJB 定义为准，正文避免混用。
