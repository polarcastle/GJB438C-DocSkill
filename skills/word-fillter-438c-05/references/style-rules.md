# 句式与表达规范（[05] 软件标准化大纲适用）

> 生成 `content` 时必须遵守以下规则；写完后逐条自查。

## 1. 大纲句式（强制）

- 规定性内容一律用"**应**"表述，不用"必须""要""应该"混用，更不得用"希望""尽量""可能""可以考虑"。
- 目标、任务类内容用陈述句客观描述："本软件标准化目标包括……""本大纲规定……"。
- 每项要求是完整陈述句，主语明确（"本大纲""本软件""标准化文件体系表"等），一条只表达一个要求。
- 列项保持模板原有编号与句式（如"a)一般要求；"），只替换实质内容，不改变列项结构。

## 2. 量化要求（强制）

- 标准化目标必须定量：软件标准化系数、可复用部件比例、标准实施检查一次通过率等一律写"数值＋%"（如"不低于 80%"）。
- 效果目标给出预计幅度：节约经费、缩短研制周期写"约 X%"。
- 任务目标给出数量：制定标准化文件 X 项、贯彻实施标准 X 项。
- 数值无项目依据时标注"待与用户确认"，**禁止凭空给数**；百分比写"不低于 80%"，不写"小于 80% 左右"。

## 3. 如实陈述原则（强制）

- 某条确实无内容或不适用时，写"本软件无……"或沿用模板的规定性表述，**禁止编造**项目实际没有的标准、文件或指标凑数，也禁止留空。
- 模板中属格式规定的内容（第 7 章）按项目实际剪裁；项目未做特殊规定的，沿用模板表述并保留"可参照""宜"等推荐性语气。

## 4. 编号与列举格式

- 条内列举用 a) b) c)（**半角右括号**，与模板一致）、1) 2) 3) 两级编号，同层编号样式一致。
- 交叉引用写"见 5.2""见表 1"，章节号与 JSON 中的 `id` 一致。
- 标准与文档名称用书名号《》，首次出现给出编号（如《GJB 438C-2021 军用软件开发文档通用要求》）。

## 5. 禁用表达

- 口语化："东西""搞""大概""差不多""之类的""等等"。
- 营销化："世界领先""极大地""完美"。
- 模糊限定："一般情况下""尽可能""较快"。若确需描述例外条件，写明条件本身（"在……条件下"）。
- 英文缩写首次出现不解释；正文术语与 `references/terminology.md` 不一致。

## 6. 一致性

- 软件名称、缩写、版本号全文一致，且与 `config.json` 封面信息一致（示例项目：示例系统任务调度软件 / XT / V1.0）。
- 同一概念全文同一称呼（如统一叫"标准化文件体系表"，不得与"标准文件体系表"混用）。
- 第 2 章引用文档表中列出的标准，第 3、4 章引用时名称、编号须一致。
