# 句式与表达规范（[03] 软件配置管理计划适用）

> 生成 `content` 时必须遵守以下规则；写完后逐条自查。

## 1. 管理要求句式（强制）

- 管理性规定一律用"**应**"表述，不用"必须""要""应该"混用，更不得用"希望""尽量""可能""可以考虑"。
- 每条规定是完整陈述句，主语明确（"本项目""配置管理员""项目负责人""供货单位"等），一条只表达一个要求。
- 规程描述采用"谁＋在什么时机＋做什么＋形成什么记录"结构，例如："配置管理员应在每次基线建立后进行全量备份，并填写备份记录。"

## 2. 量化要求（强制）

- 周期类规定必须给数值＋单位：备份周期（每周/每次基线变更后）、报告周期（每月）、审核频次（每条基线建立时一次）、保存期限（不少于五年）。
- 责任分配必须落到角色（项目负责人、配置管理员、开发人员、测试人员、质量保证人员），不得只写"相关人员"。
- 权限描述必须成对给出"角色＋权限级别"（读写/只读/无权限），并注明授权途径（经谁批准）。

## 3. 如实陈述原则（强制）

- 某条确实无内容时，写"本项目无……"或"现阶段无……，上述规程在出现相应需求时执行"，**禁止编造**供货单位、接口、采购活动凑数，也禁止留空。
- 不需要多种备份策略、不存在范围外接口等情况，直接如实说明，不得人为编造。
- 人员姓名等确实未定信息写"由项目组指定"或在 SKILL.md 收尾汇总清单中标注"待与用户确认"，不得编造真实人名。

## 4. 编号与列举格式

- 条内列举用 a）b）c）、1）2）3）分级编号，同层编号样式一致；子条款编号沿用模板给出的层级（如 5.2 的 b）项下用 1）2）3）4））。
- 交叉引用写"见 5.1""见下表"，章节号与 JSON 中的 `id` 一致。
- 文档名称用书名号《》，首次出现给出编号和版本（如《示例系统软件开发计划》（XT-SDP-V1.0））。

## 5. 禁用表达

- 口语化："东西""搞""大概""差不多""之类的""等等"。
- 营销化："国际先进""极大地""完美"。
- 模糊限定："一般情况下""尽可能""较快"。若确需描述例外条件，写明条件本身（"在……条件下"）。
- 英文缩写首次出现不解释；正文术语与 `references/terminology.md` 不一致。

## 6. 一致性

- 软件名称、缩写、版本号、标识号全文一致，且与 `config.json` 封面信息一致。
- 同一配置项/基线的标识符全文同一写法（如统一写"XT-BL-FUNC"，不得与"功能基线标识"混指）。
- 第 3 章职责表、第 5 章各条引用的角色名称必须与第 3 章正文定义一致；第 8 章日程与第 5 章活动时机不得矛盾。
